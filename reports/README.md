# AI-Assisted Vulnerability Analysis Tool
## Security Misconfiguration (HTTP Headers)

**Test Context:** Logistics & Delivery-style demo application (OWASP Juice Shop used as the authorized lab target)

---

## ⚠️ Authorized Testing Scope

This tool was tested **only** against authorized, intentionally vulnerable
local lab environments running on `localhost`:

- `http://localhost:3000` — OWASP Juice Shop (official training application, run locally via Docker)
- `http://localhost:5000` — a self-built local Flask test server (used to check for false positives)

**No live, third-party, or unauthorized systems were scanned or tested at any point.**
This tool is defensive/detection-only and does not generate or send exploit payloads.

---

## Objective

Build a defensive, AI-assisted detection component for **Security
Misconfiguration (HTTP headers)** — one of OWASP's Top 10 web application
risk categories (A05:2021) — and demonstrate the full workflow from
detection through AI-assisted interpretation to a professional report.

---

## How It Works

1. Sends a normal HTTP GET request to each authorized target URL.
2. Inspects the response headers against a rulebook of known security headers.
3. Flags headers that are missing, present with a weak value, or present when they shouldn't be (e.g. `X-Powered-By`).
4. Assigns a severity (High/Medium/Low) to each finding, with written reasoning.
5. Sends each finding to an LLM (via the Groq API) to generate a plain-English,
   clearly labeled **AI-Assisted Interpretation** — advisory only, never used
   to decide severity or status.
6. Writes a full Markdown report to `reports/security_report.md`.

## Setup & How to Run

1. Install dependencies:
```bash
   pip install -r requirements.txt
```

2. Start an authorized lab target (OWASP Juice Shop) locally:
```bash
   docker run -d -p 3000:3000 bkimminich/juice-shop
```

3. (Optional, for false-positive testing) In a separate terminal, run the local safe test server:
```bash
   python safe_test_server.py
```

4. Set your Groq API key for the current terminal session:
```bash
   $env:GROQ_API_KEY="your-key-here"
```

5. Run the scanner:
```bash
   python scanner.py
```

6. View the generated report at `reports/security_report.md`.

## Severity Methodology

Each header check has a severity rating (High/Medium/Low) with a written
justification tied to real-world impact — not a blanket "every missing
header is High severity" rule. See `scanner.py`'s `SECURITY_HEADER_CHECKS`
rulebook and each finding's `severity_reasoning` field for full detail.

---

## AI-Assisted Interpretation

Every finding in the report includes a section labeled
**"AI-Assisted Interpretation (advisory, non-deterministic)"**. This text
is generated by an LLM (via the Groq API, model `openai/gpt-oss-20b`) and
is used **only** to explain findings in plain English and flag anything
worth a human double-checking. All detection logic, status, and severity
decisions are made entirely by deterministic Python code — the AI never
determines whether something is a vulnerability.

## Testing: True Positives & False Positives

- **True Positive test:** Scanned OWASP Juice Shop (`localhost:3000`), an
  intentionally vulnerable application — confirmed the scanner correctly
  detected missing `Content-Security-Policy`, `Strict-Transport-Security`,
  `Referrer-Policy`, and `Permissions-Policy`.
- **False Positive test:** Built a local Flask server (`safe_test_server.py`)
  with all security headers deliberately configured correctly — confirmed
  the scanner produced zero findings against it.
- **Tuning:** Deliberately weakened the CSP header on the safe test server
  (`default-src *; script-src 'unsafe-inline'`) to confirm a known false
  negative gap, then added a dedicated weak-CSP-value check to close it.
  See `LIMITATIONS.md` for full detail on what this tuning does and does
  not cover.
