### Finding 1: Strict-Transport-Security — MISSING

- **Description:** Forces browsers to use HTTPS instead of HTTP.
- **Evidence:** Header 'Strict-Transport-Security' was not found in the response headers.
- **Severity:** Medium
- **Severity Reasoning:** Missing HSTS allows a possible downgrade from HTTPS to HTTP on first connection, exposing traffic to interception on untrusted networks. Rated Medium rather than High because it requires an active network-position attacker to exploit, not a remote/anonymous one.
- **Recommended Remediation:** Add the header 'Strict-Transport-Security: max-age=31536000; includeSubDomains' once the site is served over HTTPS in production.

This means that on the very first visit a user could be redirected to plain HTTP, letting a malicious network spy on their traffic.  
Because the attack requires someone positioned on the user’s network, the risk is considered medium, but a security review is still recommended.

### Finding 2: Content-Security-Policy — MISSING

- **Description:** Restricts which sources of scripts/content the page can load, mitigating XSS.
- **Evidence:** Header 'Content-Security-Policy' was not found in the response headers.
- **Severity:** High
- **Severity Reasoning:** CSP is one of the strongest available browser-side defenses against Cross-Site Scripting (XSS), a high-impact, very common vulnerability class. Its complete absence removes a major layer of defense, so this is rated High.
- **Recommended Remediation:** Add a 'Content-Security-Policy' header, starting with a restrictive baseline such as "default-src 'self'" and expanding only as needed for legitimate third-party resources.

**AI-Assisted Interpretation** *(advisory, non-deterministic — generated by an LLM, not the scanner)*:
> The website is missing the **Content‑Security‑Policy (CSP)** header. CSP tells the browser which scripts or other content it is allowed to load, which blocks a common attack called Cross‑Site Scripting (XSS). Without this header, the page has no automated browser protection against XSS.  
Because the header is completely absent, a quick check should confirm that no CSP is being sent from another sub‑resource or via JavaScript, just to be certain the site truly has no CSP at all.

### Finding 3: Referrer-Policy — MISSING

- **Description:** Controls how much URL information leaks to other sites via referrer.

- **Severity:** Low
- **Severity Reasoning:** Impact is typically limited to partial URL/metadata leakage to third-party sites when a user clicks an outbound link — rarely a direct path to full compromise, so rated Low.
- **Recommended Remediation:** Add the header 'Referrer-Policy: strict-origin-when-cross-origin' (or 'no-referrer' for stricter privacy).

**AI-Assisted Interpretation** *(advisory, non-deterministic — generated by an LLM, not the scanner)*:

This is generally harmless, but a reviewer might still want to check if the site uses many outbound links that could expose sensitive URL fragments.
